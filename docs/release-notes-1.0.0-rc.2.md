# 1.0.0-rc.2（本地候选）

此文档描述工作区中的本地候选 1.0.0-rc.2。候选尚未完成全部实机配置界面验收，也未作为 rc.2 发布或提交市场收录；它不修改已发布 rc.1 的 Release 附件。此前旧五角色 headless 成功记录属于旧版，不能作为本候选通过验收的证据。

## 本候选内容

- 扩展为六个独立映射角色：explorer（探索）、researcher（查证）、worker（实现）、tester（测试）、reviewer（审查）和 visioner（识图）。映射保存后仅新建主会话采用新版本，已有会话继续保留创建时的映射。
- 新增一步有界委派 `agent_delegate`。worker 需要精确文件清单，tester 需要完整命令清单；旧版前台 subagent 委派在插件多代理模式开启时由插件接管。DSH 0.2.1-rc.2 的原生委派返回异步 activation/subagentId，插件会在执行前指引根代理改用 `agent_delegate`，保留任务和约束，避免执行后被宿主拒绝旧格式结果；不伪造激活 ID。未知原生契约同样在执行前拒绝。角色含糊或实现要求没有明确边界时，根代理需要明确指定角色与范围。
- 根直接写入或运行命令前须进行委派评估。子代理不能嵌套委派；只读角色受宿主只读沙箱和 guard 限制，worker 只能写归属文件，tester 只能在确认的只读沙箱中按原样执行授权命令。
- 审查输出明确区分问题与正向核对证据：clean须findings为空，真实缺陷才进入findings，残余不确定性单列；矛盾报告仍被拒绝。
- 测试通过还要求每条授权命令都有宿主的实际成功退出证据；命令被拒绝或失败后，代理自报passed不能使阶段通过。兼容宿主pwsh必填description及timeoutMs，继续禁止改变工作区、环境、权限或转后台。
- 整份计划启动前检查测试命令及所有阶段所需宿主能力；缺少命令或沙箱支持时不会先执行实现。尚未关联角色生命周期的子会话工具调用默认拒绝。
- 默认没有 `prior.rootPlan` 时只运行探索并交还根决策；实现阶段没有根批准方案时不会启动 worker。交接合并约束、使受上游变化影响的旧证据失效，并同时提供摘要和完整报告原件引用。
- 为重复调用与中断恢复增加 operationId 账本。同一 operationId 回放已保存结果；`resumeFrom` 限于同一会话和相同输入，已成功阶段可跳过。结果未知或潜在写入状态不确定时要求先检查，不能盲目重试。
- 设置并发锁依赖 Node 内置 SQLite，最低 Node 运行时要求为 22.13。运行诊断比较加载构建和磁盘源码的哈希，提示需要 reload 的情况。
- 模型目录读取按通道隔离错误；失败通道会报告错误，其他成功通道仍可使用。整体目录接口故障仍可能导致页面无法读取目录。

## 使用定位与限制

本插件继续配合 `dsh-our-free-model`，让探索、查证、实现、测试、审查和识图角色使用已启用通道模型，服务于可用免费额度的分工场景。免费额度与条款由供应商决定，部分通道可能不免费，多个模型可能共享额度。插件不查询余额、不按余额调度，也不会在额度耗尽时自动换模型。

多代理开关关闭时，插件停止接管普通 subagent 请求，宿主原生委派工具仍保留；插件自身编排入口仍受开关控制。guard 与只读沙箱依赖宿主能力，不能保证隔离所有外部副作用，也不构成完整安全认证。
