# DSH 代理模型插件设计提案

状态：设计提案，尚未实现或安装。范围已确认：所有工作区共用配置。

## 用户操作

在 DeepSeek Harness 左侧主导航（插件、自动化任务、上下文洞察、技能中心所在区域）新增“代理模型”。点击后打开原生风格页面，显示 explorer、worker、tester、researcher、reviewer 五行。每行有中文职责、当前通道/模型和模型选择器。选择器支持搜索与按通道分组，只显示 dsh-our-free-model 已启用（若用户在“dsh-our-free-model”调整了模型设置 则在打开会话栏插件的时候自动更新）、可被宿主列出的模型。保存按钮统一提交五个角色，成功后提示“已保存，后续启动的新会话生效”。

配置对所有工作区和会话共用，持久保存并在重启后恢复；仅控制子代理角色路由，不改变当前主会话模型。已有任务保留启动时的路由快照。多个页面保存采用配置版本检查，避免旧页面覆盖新选择。

## 方案选择

推荐：独立 DSH 插件，左侧入口 + 五角色配置页 + 自有编排执行工具。复用已修复的引擎，角色路由由服务端读取已保存配置，而不是要求用户手动复制 JSON。

替代：只提供配置页面修改原 profile JSON。实现更轻，但普通 workflow 不一定读取它，容易出现界面修改而实际路由不变，因此不采用。

不替换内置 workflow，不修改 DSH 应用源码，也不改 dsh-our-free-model 的源码。

## 接口与数据流

1. 客户端通过 sidebar.panellist 注册左侧入口，通过 main 注册对应页面；均为现有插件使用的真实 DSH slot。
2. 插件服务端读取宿主 LLM 的当前模型目录，限定为 dsh-our-free-model 已注册的通道模型，并沿用其启用过滤。最终目录接口将在实现时根据实际源码进行契约测试，不通过猜测名称调用接口。
3. 保存时服务端再次校验 provider/model 确实存在且启用，保存全局插件自有状态，不保存或读取通道密钥给客户端。
4. 自有编排工具读取配置快照，将 roles 注入已修复引擎，再调用 workflowEngine.start，继承调用者会话和取消信号。工具参数不允许悄悄覆盖 UI 已保存的角色映射。
5. 通过随插件注册的使用说明/技能指引根代理采用该执行入口；不修改全局 AGENTS.md。
6. 使用已有工作流的失败门、分阶段交接、文件归属与并发限制；仍默认单 worker，按需要选择角色。

## 持久化与安装

拟使用插件自有状态目录 ~/.dsh/agent-model-router/，保存角色配置、版本号和必要元数据。所有工作区共用；不编辑其他插件的状态。

提供标准 package.json、host/client 入口、bundle patch、安装与卸载脚本。安装仅新增本插件文件和加载注册，保留现有 profile 条目；任何同名插件冲突先报告。卸载只移除本插件的加载项；角色设置默认保留，便于恢复。

## 异常与边界

- 已保存模型被停用或从目录消失：保留选择并标为不可用，阻止新运行，用户自行换模型。不得自动回退或改大小写。
- 模型目录读取失败：显示明确错误，不以静态旧列表冒充当前已启用目录。
- 保存失败、版本冲突、插件依赖不可用：保留旧有效配置，不报告成功。
- 已启用不代表当前请求一定成功。之前 DeepSeek 返回文本不完整的现象继续保留为验证记录，不自动替换默认路由。
- 界面不增加未经验证的 reasoning/sandbox 开关；子代理权限沿用当前会话，角色提示不能代替只读沙箱。

## 验收

- 五个角色独立选择；列表只含当前插件启用模型，使用真实 provider/model ID。
- 保存后在另一工作区可读取相同设置，重启后仍保留。
- 一次隔离只读编排验证所选路由实际进入 workflow 子代理请求；不能仅凭页面显示认定生效。
- 已在运行的任务不因 UI 保存被换模型。
- 模型停用、目录故障和并发保存冲突均有测试。
- 视觉检查左侧入口、搜索选择器、保存提示、暗色主题和窄屏显示。
- 安装前后对现有配置做差异检查，仅新增本插件注册，不重写其他配置。
- dsh-our-free-model中调整模型，通过会话栏入口进入时自动更新模型状态
