# 发布前代码安全审查

日期：2026-10-15。范围：本插件当前源码、手工开发安装/卸载、HTTP 配置接口与分层交接；不读取或发布供应商凭据，不将模拟测试视为渗透测试。

## 1.0.0-rc.2 本地候选补充审查（2026-10-17）

本节根据当前候选源码核对委派策略、阶段交接、恢复账本、并发锁与运行版本诊断。它记录实现边界，不表示新版真实多角色验收已经完成，也不扩大为完整安全审计。

- 已核对六个映射角色：explorer、researcher、worker、tester、reviewer、visioner。`agent_delegate` 要求角色与任务；worker 还要提供精确文件清单，tester 还要提供完整命令清单。普通 subagent 调用在插件模式开启时按描述尝试接管；角色含糊或实现边界不明确时需要显式指定角色和范围。插件模式关闭只停止插件接管，宿主原生委派工具仍保留。
- 在插件模式开启时，根代理直接写入和 shell 调用须先经过委派评估。子代理不能嵌套委派。角色 guard 限制工具：worker 写入须匹配文件归属，tester 只能运行清单中的原样命令且要求宿主确认只读沙箱，其他子代理为只读。上述限制依赖宿主的 `tools.guard`、执行事件和沙箱合同；无法据此证明所有工具或所有外部副作用都被隔离。
- 编排默认只探索；实现须有根代理确认的 `prior.rootPlan`。交接会返回摘要和完整报告引用；后续阶段合并约束，并让上游变化使相关旧证据失效。完整任务输入与阶段报告可能包含用户敏感内容，默认保留且没有自动清理。
- 恢复账本以会话所有者、操作 ID 和输入指纹关联操作。相同 `operationId` 会回放已保存结果；`resumeFrom` 要求同一会话和相同输入，成功阶段可跳过。若活动阶段的完成结果未知，或实现阶段未确认通过，恢复要求检查现有子会话和文件，避免盲目重复可能的写入；这仍不能消除崩溃或外部工具造成的所有不确定副作用。
- 设置写入锁使用 Node 内置 `node:sqlite`，因此源码声明 Node.js >=22.13。已核对 DSH 0.2.0-rc.2 的相关接口，但最低宿主版本与新版端到端兼容性仍待实机验证。
- 运行诊断通过已加载构建与磁盘源码哈希提示是否需要 reload。哈希或能力检测只说明版本状态与接口存在，不代表新版真实代理运行成功。
- tester的passed还须逐条匹配宿主工具实际返回的成功命令（前台、exitCode=0、未超时/取消/沙箱拒绝）；代理自述或read文件不能代替获准命令成功。实际运行曾暴露宿主pwsh必填description被错误拒绝，现允许该显示字段与timeoutMs，工作区、环境、权限和后台覆盖仍拒绝。
- 模型目录查询按通道隔离失败；一个通道查询失败时保留其他成功通道并报告部分错误。宿主目录总接口不可用时仍会整体失败。

不把本地源码检查描述为完整安全保障；也不声称它能隔离所有外部副作用、宿主行为或上游模型服务。

## 检查结果

- 本包没有 preinstall、postinstall 或 prepare 生命周期脚本；标准源码安装已在关闭脚本执行的独立 profile 中成功，并完成入口检查和卸载。
- 客户端请求使用宿主同源的 `/agent-model-router/` 接口；服务端先调用宿主 `connection.admit`，匿名读取/写入、非 JSON、超大请求和版本冲突有本地覆盖。另已核对桌面版 DSH 0.2.0-rc.2 的 dsh-client-connection 实现：admit 先检查 Host/Origin，再检查浏览器认证。对真实宿主的读取实测：匿名请求 401、外部 Origin 403、外部 Host 403，均在配置读取前拒绝。这些检查不等于完整 CSRF 渗透测试或其他版本的保证。
- 指定运行文件中未发现独立凭据收集或外部 HTTP 上传代码。模型调用通过调用会话的 workflow 执行；用户任务和报告会发送给其所选模型，不能把“插件不直接上传凭据”理解为“任务不离开本机”。
- 角色选择只接受广告目录中的启用模型，保留模型 ID 大小写，不通过请求覆盖已保存映射；配置对象不会向浏览器返回供应商凭据。
- 分层报告文件名由内部 UUID、阶段序号构造，不使用任务字符串作为磁盘路径。文件使用排他创建及 0o600；Windows 的实际保护取决于父目录 ACL。完整输入/报告可能包含用户任务中的敏感内容，默认长期保存、无自动清理。
- `stateFile`、`handoffDirectory` 是本地管理员配置入口，可重定向磁盘位置；不是 HTTP 用户控制的路径。修改配置时应检查目标路径与目录权限。
- 开发安装器只注册本包；开发卸载器只接受插件符号链接，不递归删除源目录。它不是标准 DSH 包管理器。已修复缺失 dependencies/profile 字段的处理、lstat 错误传播、卸载备份权限和链接删除失败后的 manifest 恢复，新增 4 项回归测试通过。若检测到其他进程已修改 manifest，则停止自动恢复并保留备份；跨进程检查与替换之间的竞态仍不是完全事务保证。

## 使用与清理

不要把密钥、供应商登录令牌放进任务或交接内容。完整交接位于 `~/.dsh/agent-model-router/handoffs/`，保留期由用户管理；在相关任务停止后可按运行目录清理。备份位于同一插件目录的 `backups/`，配置文件可能含本机路径，应限制目录访问。

## 结论范围

这是有明确范围的代码审查和本地验证，不是第三方认证，也不能证明宿主、依赖插件和上游模型服务不存在漏洞。真实页面与模型运行需要已登录 DSH，会单独记录成功与失败证据。
